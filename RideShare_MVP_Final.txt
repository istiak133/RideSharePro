Category 1: Rider (Customer) Features — 17 Features


Phase 1: Onboarding
Feature 1:  Phone-Based Registration   [MVP CORE]
Ki kore:
User ekta 11-digit Bangladeshi phone number enter kore (01 diye shuru). System validate kore format thik ache kina ebong ei number already registered kina. Thik thakle Twilio API diye 6-digit OTP SMS pathay. User OTP enter korle system verify kore. Correct hole ekta unique UUID diye user account create hoy, JWT token generate hoy ebong device e secure store hoy. User automatically logged in hoy — kono password lagbe na.
Validation rules:
Phone exactly 11 digits, 01 diye shuru mandatory. OTP 5 minute er moddhe valid. Max 3 bar bhul OTP dile temporary block. Ghontay max 5 bar OTP request per phone. Per IP ghontay max 50 request (spam protection).
Database tables:
users (id UUID, phone VARCHAR unique, role ENUM rider/driver, status ENUM active/blocked, created_at). otp_verifications (phone, otp_code hashed, attempts INT, expires_at TIMESTAMP, created_at).
Security:
OTP bcrypt diye hashed store hoy plain text na. Rate limiting dui layer e — phone level ebong IP level. JWT token expiry ache, refresh token system thakbe.
Feature 2:  User Profile Management   [MVP CORE]
Ki kore:
Registration er por user profile completion screen e jay. Rider der jonno mandatory: full name (min 3 char), profile photo, date of birth (18+ verify korte). Optional: email, emergency contact name + phone, preferred language. Profile photo client-side e compress hoy (max 400KB) tarpor Supabase Storage e upload hoy, public URL database e save hoy.
Driver er additional mandatory fields:
NID card photo front, NID card photo back, driving license photo, vehicle type (shudhu CAR — is release e), vehicle model, vehicle registration number, vehicle photo, bank account holder name, account number (encrypted store), bank name, branch name. Driver submit korle status 'Pending Verification' hoy — kono ride accept korte parbe na jotokhon admin approve na kore.
Validation:
Client-side real-time validation: name min 3 char, email format check, photo size/format check (jpg/png only, max 5MB before compression), age 18+ check. Server-side shob kicu re-validate hoy — client ke trust kora jay na. Photo magic number diye format verify. NID/license OCR check (readable kina).
Database tables:
user_profiles (user_id FK, full_name, photo_url, date_of_birth, email, emergency_contact_name, emergency_contact_phone, language_preference, updated_at). driver_documents (user_id FK, nid_front_url, nid_back_url, license_url, verification_status ENUM pending/approved/rejected, verified_by admin_id FK, verified_at, rejection_reason). driver_vehicles (user_id FK, vehicle_type ENUM car, vehicle_model, vehicle_year, registration_number, vehicle_photo_url). bank_accounts (user_id FK, account_holder_name, account_number encrypted, bank_name, branch_name, routing_number).


Phase 2: Ride Booking

Rider pickup point select korte pare 3 ভাবে: (1) current location button tap, (2) search box e address type korle Google Places Autocomplete suggestions dekhay, (3) map e directly tap kore pin drop. Same process e destination select kore. Duto location select hole Google Directions API call hoy — distance (km), estimated duration (min), ebong suggested route return kore.

API usage:
Google Maps SDK (map display), Google Places API (address autocomplete), Google Directions API (route + distance + ETA calculation), Geocoding API (coordinates to address conversion).
Feature 4:  Vehicle Type Selection — Cars Only   [CLIENT REQUIREMENT]
Ki kore:
Is release e rider shudhu 'Car' option dekhbe. Bike, CNG, van kono option UI te thakbe na. Car select korle system Car-specific fare rules load kore, Car driver pool theke nearby drivers khoje. Future phases e onno vehicle type add kora jabe without breaking existing logic — vehicle_type ENUM properly design korte hobe.
Database tables:
fare_rules (vehicle_type ENUM, base_fare DECIMAL, distance_rate DECIMAL, time_rate DECIMAL, minimum_fare DECIMAL, updated_at). drivers table e vehicle_type column thakbe filter er jonno.
Feature 5:  Dynamic Fare Calculation   [MVP CORE]
Ki kore:
Google Directions API theke distance ebong estimated time paowar por system fare calculate kore. Formula: final_fare = (base_fare + distance_km x distance_rate + time_min x time_rate). Result minimum_fare er niche hole minimum_fare use hoy. Tarpor surge multiplier apply hoy — nearby active rides vs available drivers er ratio diye calculate hoy (demand/supply). Ratio 1.5 er beshi hole surge start hoy, max cap 3x. Result 5 er nearest multiple e round hoy. Rider ke full breakdown dekhano hoy: base fare, distance fare, time fare, surge amount, total — transparency er jonno trust build kore.
Surge logic:
Zone wise active_rides count ebong available_drivers count compare kora hoy. Ratio >= 1.5 hole 1.2x, >= 2.0 hole 1.5x, >= 2.5 hole 1.8x, >= 3.0 hole 2.5x, extreme case e max 3.0x. Surge value Redis e cache hoy 60 second TTL diye — database hit kome.
Database tables:
fare_rules (vehicle_type, base_fare, distance_rate, time_rate, minimum_fare). surge_history (zone_id, timestamp, surge_multiplier, active_rides, available_drivers). rides table e estimated_fare, surge_multiplier, fare_breakdown JSONB store hoy.
Feature 6:  Ride Booking   [MVP CORE]
Ki kore:
Rider fare estimate dekhe 'Confirm Booking' tap kore. System ekta unique ride record create kore database e status 'searching_driver' diye. Ride ID, pickup/drop coordinates, estimated fare, surge multiplier, rider ID, selected vehicle type, booking timestamp shob store hoy. Immediate booking hole status 'searching_driver', scheduled booking hole status 'scheduled' hoy ebong scheduled_at timestamp store hoy. Ride ID rider ke return kore — screen e dekhay.
Database tables:
rides (id UUID, rider_id FK, driver_id FK nullable, pickup_lat, pickup_lng, pickup_address, drop_lat, drop_lng, drop_address, vehicle_type, status ENUM scheduled/searching_driver/driver_assigned/driver_on_way/arrived/started/completed/cancelled, estimated_fare, final_fare, surge_multiplier, fare_breakdown JSONB, pickup_otp_hash, otp_attempts INT default 0, otp_verified BOOLEAN, scheduled_at TIMESTAMP nullable, started_at, completed_at, cancelled_at, cancellation_reason, created_at).
Feature 7:  Schedule-a-Ride   [CLIENT REQUIREMENT]
Ki kore:
Rider 'Schedule a Ride' option select kore. Date picker ebong time picker dekhay — minimum 1 ghonta future, maximum 7 din future. Rider local timezone e time select kore kintu system UTC e convert kore store kore. Booking confirm hole rides table e status 'scheduled', scheduled_at UTC timestamp store hoy. Scheduled time er 15 minute age ekta background job (cron) chale jeta nearby available Car drivers ke special 'Upcoming Scheduled Ride' notification pathay. Kono driver accept na korle 10 minute age wider radius (10km) e retry hoy. Driver accept korle confirmed, na korle system 5 minute age last try kore — tarao na korle rider ke notify kore 'No driver found, please rebook'.
Cancellation policy:
Rider scheduled ride cancel korte parbe free of cost jodi scheduled time er 30 minute beshi baki thake. 30 minute er moddhe cancel hole cancellation fee apply hobe (admin configurable).
Timezone handling:
Server always UTC e store kore. Rider app device timezone detect kore local time show kore. Display er shomoy UTC → local conversion hoy. Driver notification e driver er local time dekhay.
Database tables:
rides table e scheduled_at TIMESTAMP nullable. scheduled_ride_jobs (ride_id FK, job_type ENUM 15min_notify/10min_retry/5min_final, scheduled_for TIMESTAMP, executed_at nullable, status ENUM pending/executed/failed).
Feature 8:  Driver Search Status   [MVP CORE]
Ki kore:
Booking confirm howar shonge shonge rider 'Searching for driver...' screen dekhe animated indicator shohit. Background e system PostGIS (ba Redis GeoHash) use kore 5km radius e online Car drivers khoje — sorted by distance. Top 10 driver ke FCM notification pathay simultaneously. Kono driver accept korle immediately screen change hoy 'Driver Found!'. 2 minute er moddhe kono driver accept na korle system radius 10km e baro kore re-search kore. Total 5 minute er moddhe driver na pele rider ke 'No driver available' dekhay with retry option.
Database tables:
drivers table e current_lat, current_lng, status ENUM online/offline/busy, vehicle_type thakbe geospatial query er jonno. PostGIS ST_DWithin function use hobe proximity search e.


Phase 3: Live Tracking & Ride Execution
Feature 9:  Real-Time Driver Location Tracking   [MVP CORE]
Ki kore:
Driver ride accept korar por driver app background e GPS location collect kore proti 5 second e. Ei location Firebase Realtime Database e push hoy: /driver_locations/{driver_id} path e lat, lng, heading, speed, timestamp store hoy. Rider app ei path e Firebase listener set up kore — naya data ashle automatically map e driver marker update hoy smooth animation shohit. Rider map e driver er current position, route line, ebong ETA dekhe. Driver pickup location er 100 meter er moddhe ashle rider ke 'Driver is nearby!' notification jay.
ETA calculation:
Proti 30 second e Google Directions API call hoy driver current location theke pickup point — real traffic consider kore updated ETA calculate hoy. Rider screen e countdown update hoy.
Database / Firebase structure:
Firebase Realtime DB: /driver_locations/{driver_id}: {lat, lng, heading, speed, timestamp, ride_id}. Rider disconnect hole listener automatically remove hoy memory leak prevent korte.
Feature 10:  Pickup OTP Verification   [MVP CORE]
Ki kore:
Ride create howar shomoy system random 4-digit OTP generate kore (1000-9999 range). bcrypt diye hash kore rides table e pickup_otp_hash column e store hoy — plain text kokhono store hoy na. Rider app e bold large font e code dekhay with copy button. Driver pickup location e 'I've Arrived' tap korle rider ke 'Driver has arrived' notification jay ebong rider screen e code prominently dekhay. Driver code enter kore — system bcrypt.compare() diye verify kore. Correct hole otp_verified = true, ride start possible. Wrong hole attempt count bare — max 3 attempt, 3 bar fail hole ride auto-cancel hoy ebong admin flag hoy investigation er jonno.
Edge cases:
Rider phone dead hole driver support call korte parbe. Network issue hole driver app locally encrypted code cache kore offline verify korte parbe (5 min TTL). Code forgotten hole rider app e 'Resend Code' option ache.
Database tables:
rides table e pickup_otp_hash VARCHAR, otp_attempts INT default 0, otp_verified BOOLEAN default false, otp_generated_at TIMESTAMP. otp_audit_log (ride_id FK, driver_id FK, attempt_number, success BOOLEAN, timestamp, ip_address) — investigation er jonno.
Feature 11:  Ride Progress Tracking   [MVP CORE]
Ki kore:
Ride 'started' status e gele rider app full-screen map dekhe. Map e: rider current location (blue dot), destination (red pin), driver/car icon (moving), suggested route (blue line). Bottom panel e: destination name, remaining distance (km), ETA (min), estimated fare. Driver GPS update proti 5 second e Firebase theke rider app receive kore map animate kore. Ride shesh hole 'You have arrived' notification jay.
Route recording:
Ride chalukale driver app proti 5 second e GPS point ride_route_points table e insert kore. Eta pore actual distance calculate (GPS points theke), fare verification, dispute resolution, ebong route deviation detection e use hoy.
Database tables:
ride_route_points (id, ride_id FK, lat DECIMAL, lng DECIMAL, speed DECIMAL, heading DECIMAL, recorded_at TIMESTAMP). Index on ride_id for fast retrieval.

Phase 5: Payment
Feature 13:  Cash Payment   [MVP CORE]
Ki kore:
Ride 'completed' status e gele driver app e final fare dekhay ebong 'Confirm Cash Received' button thake. Rider cash dey physically, driver button tap kore confirm kore. System payment record create kore: amount, method 'cash', status 'completed', timestamp. Platform commission (25%) ebong driver earning (75%) automatically calculate kore store kore. Payment confirmed hole rider app e receipt dekhay. Rider-o 'Confirm Payment' button dekhte parbe (optional trust layer) — dispute korte parbe jodi cash exchange na hoy.
Commission split:
Total fare er 25% platform commission, 75% driver earning. Driver cash rakhe — weekly/monthly settlement e platform ke commission dey (Cash Settlement Feature 39 e handle hoy).
Database tables:
payments (id UUID, ride_id FK unique, amount DECIMAL, payment_method ENUM cash/card, status ENUM pending/completed/failed/disputed, platform_commission DECIMAL, driver_earning DECIMAL, paid_at TIMESTAMP, receipt_url, verified_by ENUM driver/rider/system/admin, dispute_status ENUM null/reported/resolved, dispute_reason TEXT, created_at).
Feature 14:  Card Payment (Stripe)   [CLIENT REQUIREMENT]
Ki kore:
Rider profile e 'Add Card' option thake. Tap korle Stripe SDK er secure card input form khule — card number, expiry, CVV enter kore. Stripe ei data directly receive kore, backend kokhono raw card data dekhe na (PCI DSS compliant). Stripe ekta payment_method_id return kore jeta database e save hoy. Ride shesh hole rider 'Pay by Card' select korle Stripe PaymentIntent create hoy server-side, charge hoy. Success hole payment record 'completed'. Fail hole rider ke fallback e cash option offer kora hoy. Card 'Last 4 digits' ebong brand (Visa/Mastercard) dekhay — full number na.
Sandbox to production:
Development e Stripe test keys use hobe. Handover e production keys swap korle live hobe — kono code change lagbe na. Sandbox e test card numbers diye full flow tested thakbe.
Database tables:
payment_methods (id UUID, user_id FK, stripe_payment_method_id VARCHAR, last4 VARCHAR 4, brand VARCHAR, is_default BOOLEAN, created_at). payments table e stripe_payment_intent_id VARCHAR column thakbe.
Feature 15:  Bilingual UI — English + 2nd Language   [CLIENT REQUIREMENT]
Ki kore:
Entire app er shob text (buttons, labels, messages, errors, notifications) 2ta language file e separated: /locales/en.json ebong /locales/[lang].json (client supplied). App start e user er saved language preference load hoy. Settings e language toggle thake — tap korle instantly switch hoy, app restart lagbe na. Date format, time format, currency display o language onujayi change hoy. Backend error messages o translated version pathay.
Language file structure:
Key-value pairs — e.g. {'booking.confirm': 'Confirm Booking', 'payment.cash': 'Cash Payment'}. Nested structure use hobe category wise. Client 2nd language er .json file provide korbe — developer shudhu fill in korbe, structure already ready thakbe.
Database tables:
user_profiles table e language_preference VARCHAR ('en' ba language code) column thakbe.


Phase 6: Post-Ride
Feature 16:  Rating & Review System   [MVP CORE]
Ki kore:
Payment confirm howar por rider ke automatically rating screen dekhay — skip possible kintu next ride e reminder ase. Rider driver ke 1-5 star dey ebong optional text comment likhte pare. Driver o rider ke rate kore. Shob rating submit hole system user er average rating recalculate kore profile e update kore. Rating history store hoy.
Rating impact:
Driver er average rating 4.0 er niche gele matching algorithm e lower priority pabe. 3.5 er niche gele admin review flag hoy. Consistently kharap rider (3.0 er niche) ke driver decline korte parbe without penalty.
Database tables:
ratings (id UUID, ride_id FK unique, rated_by FK, rated_user FK, role ENUM rider_rates_driver/driver_rates_rider, stars INT 1-5, comment TEXT nullable, created_at). users table e average_rating DECIMAL ebong total_ratings INT column thakbe — update trigger ba application layer e recalculate.
Feature 17:  Push Notifications   [MVP CORE]
Ki kore:
Firebase Cloud Messaging (FCM) use kore. User registration er shomoy device FCM token collect kore database e save hoy. Token expire hole automatically refresh hoy. Notifcation pathano hoy ei events e — Rider er jonno: driver accepted, driver on way, driver arrived (100m e), ride started, ride completed, payment confirmed, scheduled ride reminder (15 min age). Driver er jonno: new ride request, ride request expired, rider cancelled, payment received, document approved/rejected. Tap korle notification relevant screen e deep link kore niye jay.
Database tables:
device_tokens (user_id FK, token VARCHAR, platform ENUM ios/android, updated_at). notifications_log (user_id FK, type VARCHAR, title, body, data JSONB, sent_at, delivered BOOLEAN) — delivery tracking er jonno.
